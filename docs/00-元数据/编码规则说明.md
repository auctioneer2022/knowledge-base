# 编码规则说明

定义知识库条目的唯一标识（id）编码规则与文档元数据（frontmatter）字段规范，确保所有条目可被唯一寻址、准确分类、机器可读，为 AI 检索与知识关联网络提供基础。

## 一、id 编码规则

格式：`前缀-序号` 或 `前缀-子域-序号`。前缀采用大写英文，对应十大知识领域：

| 前缀 | 领域 | 目录 |
|------|------|------|
| LAW  | 法律法规 | 01-法律法规 |
| CAS  | 会计准则 | 02-会计准则 |
| CSA  | 审计准则 | 03-审计准则 |
| TAX  | 税法法规 | 04-税法法规 |
| IND  | 行业知识 | 05-行业知识 |
| TPL  | 实务模板 | 06-实务模板 |
| CASE | 案例库   | 07-案例库 |
| MTH  | 工具方法 | 08-工具方法 |
| TRN  | 培训资源 | 09-培训资源 |
| SUS  | 可持续披露准则 | 10-可持续披露准则 |
| META | 元数据   | 00-元数据 |

子领域扩展前缀（用于细化同一领域下的子类）：
- `REG`：监管规则（隶属 03-审计准则 / 05-监管规则）
- `CSCE`：职业道德与质量管控（隶属 03-审计准则）
- `QMS`：质量管理准则（隶属 03-审计准则 / 职业道德与质量管控）
- `CAS-MA`：管理会计应用指引（隶属 02-会计准则 / 应用指引体系）
- `CSA-IND`：注册会计师独立性准则（隶属 03-审计准则 / 职业道德与质量管控）

序号规则：同一��缀下从 `001` 递增；索引页（index）统一使用 `前缀-INDEX` 或 `前缀-子域-INDEX`（如 `CAS-14-001`、`CASE-01-INDEX`）。

## 二、frontmatter 字段规范

所有知识文档须在文件头部以 YAML Front Matter 声明元数据。字段分「必填」「推荐」两档：

**必填字段**
- `id`：唯一标识，遵循上述编码规则，全库唯一。
- `category`：分类路径，格式 `顶级领域/子领域`，如 `会计准则/具体准则`。

**推荐字段**
- `title`：文档标题（索引页、方法类、行业类建议必填，便于导航与检索）。
- `keywords`：关键词数组，提升检索命中。
- `doc_number`：发文字号（法规 / 准则类）。
- `effective_date`：生效日期，格式 `YYYY-MM-DD`。
- `status`：效力状态，如 现行有效 / 已废止 / 待生效。
- `source`：来源（法规 / 案例类必填，标注权威出处）。
- `date`：发布或整理日期（案例 / 资讯类）。
- `related_ids`：关联条目 id 列表，用于构建知识关联网络（推荐逐步补全）。
- `tags`：标签数组（可选，配合 MkDocs tags 插件）。

**字段书写约定**
- 日期统一使用 `YYYY-MM-DD`。
- 数组采用 `[a, b, c]` 形式。
- 逐字转录类条目须保留原文结构与发文字号，并在正文首行以 `> 发文字号 | 发布日期` 标注来源。
