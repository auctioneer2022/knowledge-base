# IT审计基本方法

> 本文件为注册会计师在信息化环境下执行审计工作提供IT审计方法指引，涵盖IT审计框架、一般控制与应用控制审计程序以及常用审计工具与技术。

## 一、IT审计概述

### 1.1 IT审计的定义

IT审计是指对信息系统的相关控制进行识别、评估和测试的过程，以确定信息系统能否有效保护资产安全、维护数据完整、支持组织目标实现。在财务报表审计中，IT审计是了解和测试与审计相关的内部控制的重要组成部分。

IT审计的核心内涵包括：

- **系统可靠性**：评估信息系统能否持续、稳定地提供可靠的财务数据；
- **数据完整性**：验证系统中存储和处理的财务数据是否完整、准确；
- **控制有效性**：评价信息系统一般控制和应用控制的设计与运行有效性；
- **合规性**：确认信息系统的运行符合相关法律法规和内部制度要求。

### 1.2 IT审计的目标

IT审计在财务报表审计中的主要目标包括：

1. **了解IT环境**：了解被审计单位的IT环境，包括系统架构、关键应用程序、数据库平台、网络基础设施等；
2. **识别IT风险**：识别信息技术环境可能对财务报表产生重大影响的风险；
3. **评估控制设计**：评估IT一般控制和应用控制的设计合理性；
4. **测试控制运行**：测试IT控制在审计期间内的运行有效性；
5. **确定审计策略**：根据IT控制评估结果确定实质性程序的性质、时间安排和范围。

### 1.3 IT审计的范围

IT审计的范围取决于被审计单位对信息系统的依赖程度，通常包括：

- **基础设施层**：服务器、网络设备、存储设备、操作系统等；
- **应用系统层**：ERP系统（如SAP、Oracle）、财务系统、业务系统等；
- **数据层**：数据库管理系统、数据仓库、数据接口等；
- **人员与流程层**：IT组织架构、IT管理制度、操作流程等。

### 1.4 IT审计与财务报表审计的关系

在信息化环境下，财务报表的生成高度依赖信息系统。IT审计与财务报表审计的关系体现在：

- **审计准则要求**：《中国注册会计师审计准则第1211号——通过了解被审计单位及其环境识别和评估重大错报风险》要求注册会计师了解与审计相关的内部控制，包括与财务报告编制相关的信息技术环境；
- **控制依赖路径**：当注册会计师计划依赖自动化控制或IT一般控制时，必须对相关IT控制进行测试；
- **实质性程序的补充**：即使不依赖IT控制，注册会计师仍需考虑IT环境对实质性程序设计的影响；
- **数据可靠性**：当审计证据以电子形式存在时，注册会计师需要评估电子证据的可靠性。

## 二、IT审计框架

### 2.1 COBIT 2019框架

COBIT（Control Objectives for Information and Related Technologies）是国际公认的IT治理与管理框架。COBIT 2019是该框架的最新版本，为组织提供了IT治理和管理的全面指引。

**COBIT 2019的核心原则**：

- **原则一**：满足利益相关者需求——IT治理应平衡利益相关者的利益，确保IT投资创造业务价值；
- **原则二**：覆盖企业端到端——将IT治理整合到企业治理体系中，覆盖所有功能和流程；
- **原则三**：应用单一整合框架——与其他治理框架（如COSO、ISO 38500）保持一致；
- **原则四**：实现整体方法——考虑所有治理和管理要素及其相互关系；
- **原则五**：区分治理与管理——明确治理层和管理层的职责边界；
- **原则六**：根据企业需求定制——根据企业的规模、行业、IT角色等因素进行裁剪。

### 2.2 IT一般控制与应用控制

IT控制分为一般控制（IT General Controls, ITGC）和应用控制（Application Controls）两大类，二者共同构成信息系统控制体系。

**IT一般控制（ITGC）**：

IT一般控制是指对信息系统整体环境进行的控制，适用于所有应用程序、系统和数据。IT一般控制是应用控制有效性的基础。主要包括：

- **IT治理**：IT组织架构、职责分离、政策制度体系；
- **访问安全控制**：逻辑访问控制、物理访问控制、网络安全控制；
- **程序变更管理**：系统变更的授权、测试、审批和部署控制；
- **计算机运行**：批处理作业控制、备份与恢复、事件管理；
- **业务连续性**：灾难恢复计划、业务连续性计划。

**应用控制**：

应用控制是指嵌入在应用程序中的控制，用于确保交易数据的完整性、准确性和授权。主要包括：

- **输入控制**：数据录入验证、输入完整性检查、格式校验；
- **处理控制**：自动计算、数据转换验证、批处理控制；
- **输出控制**：输出结果核对、分发控制、异常报告。

**二者关系**：IT一般控制是应用控制有效运行的基础。如果IT一般控制存在缺陷（如程序变更管理不当），即使应用控制设计合理，其运行有效性也可能受到影响。

## 三、IT一般控制审计

### 3.1 IT治理审计

IT治理审计关注被审计单位IT管理的组织基础和制度保障。

**审计要点**：

- **IT组织架构**：了解IT部门设置、汇报关系、关键岗位配置；
- **职责分离**：评估IT部门中系统开发、运维、安全管理等职责是否有效分离；
- **IT策略与规划**：审查IT战略是否与业务目标一致，IT投资是否经过合理审批；
- **政策制度体系**：检查IT管理制度是否健全，包括信息安全政策、变更管理政策、备份策略等；
- **IT人力资源管理**：评估IT人员配备是否充足，关键岗位是否有继任计划。

**常用审计程序**：

1. 获取并审阅IT组织架构图和岗位职责说明；
2. 检查IT管理委员会会议纪要，了解IT决策过程；
3. 审阅IT管理制度文件，评估制度的完整性和时效性；
4. 访谈IT负责人，了解IT治理实际运作情况；
5. 检查关键IT岗位的人员配备和胜任能力。

### 3.2 访问安全控制审计

访问安全控制审计是IT审计中最关键的领域之一，直接影响系统数据的安全性和可靠性。

**逻辑访问控制审计**：

- **用户身份认证**：检查密码策略（复杂度、有效期、锁定阈值）、多因素认证实施情况；
- **权限管理**：审查用户权限分配是否遵循最小权限原则和职责分离原则；
- **用户生命周期管理**：检查用户创建、变更、注销流程的控制措施；
- **特权账户管理**：评估管理员账户的使用控制和监控措施；
- **定期权限复核**：检查是否定期进行用户权限复核并及时清理冗余权限。

**物理访问控制审计**：

- **机房安全**：检查机房门禁系统、监控摄像、环境控制（温湿度、消防）；
- **终端安全**：评估工作站的安全措施，如锁屏策略、USB端口管控；
- **设备管理**：检查设备进出机房的登记制度。

**网络安全控制审计**：

- **网络架构**：审查网络分区、防火墙配置、入侵检测系统；
- **远程访问**：评估VPN、远程桌面等远程访问方式的安全控制；
- **漏洞管理**：检查系统补丁更新和漏洞扫描机制。

### 3.3 程序变更管理审计

程序变更管理审计关注信息系统变更过程的可控性。

**审计要点**：

- **变更请求管理**：检查所有变更是否经过正式申请和审批流程；
- **变更测试**：评估变更上线前是否经过充分的测试（功能测试、回归测试、用户验收测试）；
- **变更审批**：检查变更审批权限是否适当，职责分离是否有效；
- **版本管理**：评估源代码版本管理机制是否健全；
- **紧急变更**：检查紧急变更的事后审批和补充测试程序；
- **变更追溯**：验证变更实施后是否可以追溯到原始请求。

**常用审计程序**：

1. 获取审计期间内的变更清单，与系统变更日志进行核对；
2. 抽取样本检查变更请求表、测试报告、审批记录；
3. 对比生产环境与开发环境的程序版本差异；
4. 检查开发人员是否拥有生产环境的访问权限（职责分离测试）；
5. 验证紧急变更是否按规定执行事后审查。

### 3.4 计算机运行审计

计算机运行审计关注信息系统日常运行的稳定性和可控性。

**审计要点**：

- **批处理作业**：检查批处理作业调度、监控和异常处理机制；
- **作业调度管理**：评估作业调度工具的使用和作业执行日志的完整性；
- **备份与恢复**：检查数据备份策略（全量/增量）、备份频率、备份介质保管、恢复测试记录；
- **事件管理**：评估IT事件分类分级、响应时效、根因分析机制；
- **问题管理**：检查重复性事件的根本原因分析和纠正措施。

### 3.5 业务连续性审计

业务连续性审计评估被审计单位在面临灾难或重大故障时维持关键业务运行的能力。

**审计要点**：

- **业务连续性计划（BCP）**：检查BCP的制定、审批和更新情况；
- **灾难恢复计划（DRP）**：评估DRP的完整性，包括RTO（恢复时间目标）和RPO（恢复点目标）的设定；
- **演练与测试**：检查BCP/DRP是否定期演练，演练结果是否用于改进计划；
- **异地备份**：评估关键数据和系统的异地备份安排。

## 四、IT应用控制审计

### 4.1 输入控制审计

输入控制审计关注数据进入信息系统时的准确性和完整性。

**主要审计程序**：

- **数据录入验证**：检查系统是否对关键字段进行格式校验、范围校验、逻辑校验；
- **必填字段控制**：验证系统是否强制要求填写关键字段；
- **重复输入检查**：评估系统对重复录入的检测和拦截能力；
- **批量导入控制**：检查批量数据导入的校验机制和错误处理流程；
- **接口数据传输**：评估系统间接口数据传输的完整性和准确性控制。

### 4.2 处理控制审计

处理控制审计关注数据在系统内部处理过程中的正确性。

**主要审计程序**：

- **自动计算验证**：验证系统自动计算逻辑（如折旧计算、利息计算、税额计算）的正确性；
- **数据转换控制**：检查数据格式转换、单位换算等处理逻辑的正确性；
- **批处理平衡**：验证批处理过程中的输入-处理-输出平衡控制；
- **截止日期控制**：检查系统对会计期间截止日期的控制措施；
- **异常处理**：评估系统对处理异常（如除数为零、溢出等）的处理机制。

### 4.3 输出控制审计

输出控制审计关注系统输出结果的准确性和分发安全性。

**主要审计程序**：

- **输出核对**：检查系统输出结果是否经过适当核对；
- **报表生成控制**：评估自动报表生成的参数设置和逻辑控制；
- **输出分发控制**：检查敏感输出的分发权限和保密措施；
- **异常报告**：评估系统对异常输出（如负数余额、超限额交易）的报警机制。

## 五、信息系统审计程序

### 5.1 了解系统环境

**目标**：全面了解被审计单位的信息系统环境，为后续审计工作奠定基础。

**工作步骤**：

1. **IT环境调查**：通过问卷和访谈了解IT基础设施、关键应用系统、数据库平台、网络架构；
2. **系统依赖评估**：评估财务报表编制对信息系统的依赖程度，识别关键系统和关键接口；
3. **IT控制框架了解**：了解被审计单位的IT控制框架，包括一般控制和应用控制的总体设计；
4. **IT变更情况了解**：了解审计期间内信息系统的重大变更情况（如系统升级、新系统上线）；
5. **IT事件回顾**：回顾审计期间内发生的重大IT事件和安全事件。

### 5.2 风险评估

**目标**：识别IT环境中可能导致财务报表重大错报的风险。

**工作步骤**：

1. **IT风险识别**：识别IT环境中的潜在风险因素，如系统复杂性、数据集中度、接口依赖等；
2. **控制风险评估**：评估IT一般控制和应用控制的有效性对财务报表审计风险的影响；
3. **特别风险考量**：考虑IT环境是否产生或加剧特别风险（如收入确认中的自动化操纵风险）；
4. **风险排序**：对识别的IT风险进行排序，确定审计重点。

### 5.3 控制测试

**目标**：测试IT控制的设计和运行有效性。

**工作步骤**：

1. **控制设计评估**：评估IT控制的设计是否合理，能否有效防止或发现错报；
2. **运行有效性测试**：
   - **询问**：与IT人员和控制执行人员进行访谈；
   - **观察**：观察控制执行的实际过程；
   - **检查**：检查控制执行的文档记录（如审批单、测试报告）；
   - **重新执行**：重新执行控制程序以验证其有效性；
3. **自动化控制测试**：对于自动化控制，采用"一次测试加IT一般控制验证"的方法——即测试一次控制逻辑的有效性，同时验证IT一般控制（特别是变更管理）确保控制逻辑未被篡改；
4. **样本量确定**：根据控制频率和重要性确定测试样本量。

### 5.4 实质性程序

**目标**：在IT控制测试基础上，设计和执行实质性程序。

**工作步骤**：

1. **计算机辅助审计技术（CAATs）**：运用数据提取和分析工具对电子数据执行实质性测试；
2. **数据完整性验证**：验证从信息系统提取的数据的完整性和准确性；
3. **自动化分析**：利用数据分析工具执行趋势分析、异常检测等实质性程序；
4. **电子证据可靠性**：评估电子审计证据的可靠性，必要时获取额外佐证。

## 六、常用IT审计工具与技术

### 6.1 计算机辅助审计技术（CAATs）

CAATs是IT审计中的核心技术手段，主要包括：

**通用数据分析工具**：

- **ACL/IDEA**：专业的审计数据分析软件，支持数据提取、转换、分析和抽样；
- **Excel/Power Query**：适用于中小规模数据的分析和处理；
- **Python/R**：用于复杂数据分析和自定义审计脚本开发；
- **SQL查询**：直接查询数据库获取审计数据。

**CAATs的主要应用场景**：

- **数据完整性测试**：验证数据记录的完整性和一致性；
- **异常交易识别**：通过数据分析识别异常模式和异常交易；
- **重复检测**：检测重复的付款、发票或记录；
- **Benford定律分析**：利用数字频率分布检测数据异常；
- **趋势分析**：对关键数据进行时间序列分析。

### 6.2 数据提取与分析

**数据提取方法**：

- **直接数据库访问**：通过SQL查询直接从数据库提取数据；
- **系统导出**：通过系统内置的导出功能获取数据文件；
- **API接口**：通过系统API获取结构化数据；
- **屏幕抓取**：当无法直接获取数据时，通过自动化工具从系统界面提取数据。

**数据验证要求**：

- **完整性验证**：将提取数据的记录数、金额合计与系统报表进行核对；
- **准确性验证**：抽取样本与原始凭证进行核对；
- **时效性验证**：确认提取数据的时间范围覆盖审计期间。

### 6.3 系统日志审查

**审计日志分析**：

- **用户活动日志**：审查用户登录、权限变更、敏感操作等日志记录；
- **系统事件日志**：审查系统启动、关闭、异常、错误等事件日志；
- **安全事件日志**：审查安全告警、入侵尝试、病毒检测等日志；
- **数据库审计日志**：审查数据库的DDL/DML操作日志。

**日志审查技术**：

- **日志关联分析**：将多个系统的日志进行关联分析，识别异常行为模式；
- **时间线分析**：构建关键事件的时间线，发现异常时间点的操作；
- **阈值分析**：设置阈值（如非工作时间登录次数），识别异常活动；
- **用户行为分析**：分析用户行为模式，识别偏离正常模式的行为。

## 七、IT审计工作底稿编制要点

### 7.1 底稿基本要求

IT审计工作底稿应包含以下基本要素：

- **审计目标**：明确本次IT审计的具体目标；
- **审计范围**：说明审计覆盖的系统、期间和控制领域；
- **审计方法**：描述采用的审计程序和技术方法；
- **审计发现**：详细记录测试过程、发现的问题和获取的证据；
- **审计结论**：基于审计发现得出控制有效性评价结论；
- **整改建议**：针对发现的问题提出改进建议。

### 7.2 底稿索引与关联

IT审计底稿应与以下工作底稿建立索引关联：

- **风险评估底稿**：IT风险评估结果应与总体风险评估底稿关联；
- **控制测试底稿**：IT控制测试结果应与相关财务报表科目的控制测试底稿关联；
- **实质性程序底稿**：CAATs分析结果应与相关科目的实质性程序底稿关联；
- **管理建议书**：IT审计发现的重要缺陷应纳入管理建议书。

### 7.3 电子证据管理

IT审计中获取的电子审计证据应特别注意：

- **数据来源记录**：记录电子数据的来源系统、提取方法、提取时间；
- **数据完整性**：通过哈希值校验、记录数核对等方式确保数据完整性；
- **数据保管**：确保电子数据在审计期间内的安全保管；
- **可追溯性**：确保审计结论可以追溯到原始电子数据。

### 7.4 常见IT审计发现示例

以下为IT审计中常见的控制缺陷类型：

| 控制领域 | 常见缺陷 | 风险影响 |
|----------|----------|----------|
| 访问控制 | 用户权限未按职责分离原则配置 | 未经授权的交易处理 |
| 访问控制 | 离职人员账户未及时注销 | 未授权访问风险 |
| 变更管理 | 开发人员拥有生产环境访问权限 | 程序被未授权修改 |
| 变更管理 | 变更未经充分测试即上线 | 系统错误或数据丢失 |
| 备份恢复 | 未定期进行数据恢复测试 | 数据恢复能力未经验证 |
| 运行控制 | 批处理异常未及时跟进处理 | 数据处理不完整 |
| 物理安全 | 机房门禁记录未定期审查 | 未授权物理访问 |
