### 3.2 功能/场景覆盖缺口（模块未覆盖）

1. **税务实操工具缺位**：仅有框架，缺「税负率测算、纳税调整计算、税收优惠适用性判断、发票风险扫描」等一线高频工具。
2. **管理会计/预算工具空白**：缺本量利分析（CVP）、全面预算编制方法、标准成本差异分析、经营预测模型——这些是代账/咨询业务的直接增值点。
3. **可代码化"计算型"工具缺位**：模块偏"知识型"，缺"输入数据→出结果"的交互工具，例如：
   - 审计抽样计算器（样本量、置信水平→取样）
   - 本福德律自动检测（导入数据→偏差报告）
   - Z-Score / F 分数自动测算
   - 现金流预警阈值判定
4. **成本审计专题空白**：制造业成本核算审计、工程项目成本审计、研发费归集审计缺少独立方法卡片（目前散见于检查清单）。
5. **专项审计方法空白**：政府补助审计、金融工具审计、收入循环舞弊专项、关联交易审计等未独立成篇。
6. **数据质量/数据治理方法缺位**：MTH-04 偏分析模型，缺"数据质量评估、字段校验、口径治理"前置方法。
7. **前沿方法滞后**：ESG/可持续信息鉴证、AI 模型审计、数据资产入表评估等新兴领域尚未覆盖。

### 3.3 智能化/交互化缺口

- 现有内容均为静态 Markdown，无可执行组件、无参数化模板、无示例数据集。
- 检查清单为表格，未结构化（不可勾选、不可生成底稿）。
- 公式未封装，一线需手动重算。

  2. `sampling-calculator` Skill —— 基于 MTH-01-001，审计抽样样本量计算。
  3. `checklist-assistant` 一线工具 —— 基于 MTH-05-001/002，结构化勾选生成底稿。

## 六、结论

1. **覆盖广度达标，厚度不均**：9 大子模块框架完整，但 4 个文件（财务预警、合并报表、税务 2 项）为占位内容，拉低整体可用性。
2. **AI 转化基础已具备**：MTH-04（数据模型/异常检测）、MTH-01-001（抽样）、MTH-05（检查清单）已具备直接封装为 Skill / 一线智能工具的条件，建议作为 P0 优先落地。
3. **最大杠杆点在税务与财务预警**：二者业务价值高、复用性高，但内容薄，补实后可形成高频实用工具，是投入产出比最高的扩充方向。
4. **知识体系应从"静态文档"向"可计算工具"演进**：在保持知识深度的同时，优先把高成熟度方法工程化，是提升一线使用率的关键。
